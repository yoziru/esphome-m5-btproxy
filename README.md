# M5Stack AtomS3 / NanoC6 BTProxy

Turn your M5Stack AtomS3 Lite or NanoC6 into a bluetooth proxy for Home Assistant

## Boards

Pick the config for your hardware:

| Board | Device Builder package | CLI |
|-------|------------------------|-----|
| **M5Stack NanoC6** | `esphome-m5-btproxy-m5stack-nanoc6.dashboard.yml` | `BOARD=m5stack-nanoc6` |
| **M5Stack AtomS3** | `esphome-m5-btproxy-m5stack-atoms3.dashboard.yml` | `BOARD=m5stack-atoms3` |
| **M5Stack Atom Lite** | `esphome-m5-btproxy-m5stack-atom.dashboard.yml` | `BOARD=m5stack-atom` |
| **AtomS3 + I2C sensor** | `esphome-m5-btproxy-m5stack-atoms3-i2c.dashboard.yml` | `BOARD=m5stack-atoms3-i2c` |
| **NanoC6 + I2C sensor** | `esphome-m5-btproxy-m5stack-nanoc6-i2c.dashboard.yml` | `BOARD=m5stack-nanoc6-i2c` |

## Installation

### ESPHome Device Builder (recommended)

If you run the [ESPHome add-on](https://esphome.io/guides/getting_started_hassio.html) in Home Assistant:

1. For a new, unflashed board, select **Create configuration** → **Create new project** and complete the name and Wi-Fi setup. For a board already running this project's firmware, use **Adopt** instead.
2. Open the device's YAML editor. Keep the generated `esphome`, `api`, and `wifi` sections, but remove the generated `esp32:` section. The board package below supplies the correct target and framework settings.
3. Add these entries to the `secrets.yaml` used by your ESPHome configuration:

```yaml
wifi_ssid: "your-wifi-ssid"
wifi_password: "your-wifi-password"
wifi_hotspot_password: "12345678"
ota_password: "a-unique-high-entropy-password"
api_encryption_key: "your-api-encryption-key"
```

4. Add the OTA password to the top-level `substitutions` section:

```yaml
substitutions:
  # The left-hand name is fixed. Change only the secret name on the right.
  ota_password: !secret ota_password
```

5. Add the board package under the top-level `packages` section. It provides the matching `esp32:` target and the required current ESPHome OTA configuration (`ota: - platform: esphome`). Do not add separate `esp32:` or `ota:` sections. For an M5Stack NanoC6:

```yaml
packages:
  yoziru.esphome-m5-btproxy:
    url: https://github.com/yoziru/esphome-m5-btproxy.git
    ref: main
    files: [esphome-m5-btproxy-m5stack-nanoc6.dashboard.yml]
```

6. Save and **Install**. Future firmware updates are applied from this same device card with **Update**.

Use the matching `.dashboard.yml` file from the board table above for other hardware.

For example, an adopted NanoC6 with the YAML generated by current ESPHome Device Builder should look like this. Preserve the generated name, friendly name, API key, and Wi-Fi secrets from your device.

```yaml
substitutions:
  name: m5-btproxy-a1b2c3
  friendly_name: M5 BTProxy a1b2c3
  ota_password: !secret ota_password

packages:
  yoziru.esphome-m5-btproxy:
    url: https://github.com/yoziru/esphome-m5-btproxy.git
    ref: main
    files: [esphome-m5-btproxy-m5stack-nanoc6.dashboard.yml]

esphome:
  name: ${name}
  name_add_mac_suffix: false
  friendly_name: ${friendly_name}

api:
  encryption:
    key: !secret api_encryption_key

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
```

Add an `ota_password` secret before installing. Use a unique, high-entropy password; it protects the device's OTA update endpoint.

### CLI

Copy `secrets.yaml.example` → `secrets.yaml`, fill in WiFi + OTA + API key, then build for your board:

```sh
BOARD=m5stack-nanoc6 make compile && BOARD=m5stack-nanoc6 make upload
```

See `make help` for all targets (`validate-config`, `validate-dashboard-config`, `logs`, `clean`).
